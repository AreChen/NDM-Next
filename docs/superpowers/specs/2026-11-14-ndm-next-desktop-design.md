# NDM Next Windows 桌面下载器设计

状态：用户已确认，正在实施。本文记录已讨论的产品目标和技术选择；探索性样例不是产品代码。

## 目标与范围

在现有 NDM Next 仓库中开发独立的 Windows 下载器，保留现有浏览器扩展，并允许扩展选择新桌面端或原版 Neat Download Manager 作为后端。新桌面端不依赖原版程序。扩展与桌面端分别管理版本，仓库维持 MIT 许可，并遵守第三方组件的独立许可要求。

首个正式版本一次交付以下功能，而不是把 FTP 或 HLS 留到后续版本：

- HTTP/HTTPS 下载、多连接分段、暂停、断点续传、任务管理、并发和限速设置；支持代理、认证及更新过期链接。
- FTP、FTPS、SFTP，以及常见 HLS 点播和直播：TS、fMP4、AES-128、清晰度选择、独立音轨；优先输出 MP4，必要时尝试 MKV，尽可能直接封装而不转码。直播停止后保留已录部分，缺段或无法输出时明确提示。
- 中文和英文界面，现代风格，亮色、暗色及跟随系统；浏览器接管和现有站点、大小、文件类型过滤。
- 仅提供安装版。目标是 Windows 10 1903 及更高版本、Windows 11 22H2 及更高版本的 x64；Windows ARM64 只有在完成构建与实机运行验证后才发布。兼容性以实际测试为准。

不包括绕过 DRM、无法合法解密的受保护流、对所有网站或媒体格式的兼容保证，也不提供便携版。未知输入不能静默输出损坏文件或报告成功。

## 已选方案与取舍

1. **Rust 1.100 + GPUI Kit：已选。** 适合制作用户要求的现代界面和主题，沿用扩展的紫蓝品牌色。固定并验证 GPUI Kit 及其配套 GPUI 版本，避免混用不兼容的不同版本。Rust 处理核心业务，必要的系统接口封装 `unsafe` 边界；第三方原生库并非全部由 Rust 编写。
2. **Rust + 原生 Win32 界面：备选。** 最小样例占用更低，但完整的现代组件、深色主题和无障碍支持需要更多自行实现。用户选择继续使用 GPUI Kit；必要时可根据实际性能数据重新评估界面架构。
3. **Rust 媒体处理优先，必要时 FFmpeg 兜底：已选。** 常见 HLS 输入优先由 Rust 媒体处理代码封装；若不能可靠覆盖本设计约定的输入或输出，安装包可包含经许可审查的精简 FFmpeg，并只在对应任务需要时启动。FFmpeg 是独立的非 Rust 程序，增加的包体积和运行时开销须实测。若使用 FFmpeg，核对实际构建选项、依赖、对应源码、许可证和分发方式；不把用户机器现有、未经审查的 FFmpeg 当成可发布组件。

已在本机用 Rust 1.100 编译 GPUI Kit 最小样例，并对本地合成的 TS、fMP4、双音轨、AES-128 和简单直播列表更新进行媒体试验。试验用独立工具生成和校验样本，媒体封装路径未调用 FFmpeg；这不代表已验证全部真实网站、媒体格式或产品性能。

## 桌面程序与用户体验

界面使用侧边栏和任务列表，突出正在下载、已完成和其他任务状态；提供新建下载、暂停/继续、删除、查看速度及进度等操作。视觉结构可按实现时的实际布局调整，但须保持清晰、现代、可用：

```text
NDM Next       搜索                         新建下载
┌───────────┬──────────────────────────────────────┐
│ 全部任务   │ 文件名       进度       速度   状态 │
│ 正在下载   │ …                                      │
│ 已完成     │                                        │
│ 设置       │                                        │
└───────────┴──────────────────────────────────────┘
```

主题可手动选择亮色、暗色或跟随系统；语言可选择中英文。关闭窗口进入托盘，下载继续；开机自启默认关闭，用户可自行开启。浏览器接管符合条件的任务时，可按需启动程序。无任务时不进行无意义的高频轮询。

手动暂停的任务在重启后保持暂停；其他未完成任务可自动恢复，且提供关闭自动恢复的设置。删除已完成项目默认只删除记录、保留文件；删除未完成项目时询问是否一并删除临时文件。目标文件名冲突时自动选择不覆盖现有文件的名称。

建议以本地事务性数据库保存任务、设置、续传状态和持久交接状态。数据库引擎由实现者选择；涉及 C 库时应明确记录依赖、许可证和原生代码边界。凭据、Cookie、令牌和相关敏感任务数据使用 Windows 当前用户保护机制保存；不将其写入普通日志，并提供清除方式。

## 下载核心

按协议隔离实现并提供统一任务状态、取消和进度接口。HTTP/HTTPS 优先探测分段能力；服务端不支持 Range、长度未知或返回不一致时安全退回单连接。分段必须验证响应状态、`Content-Range`、长度和资源标识；续传前检查 ETag 或 Last-Modified 等可用验证器，资源发生变化时不能拼接旧数据。更新过期链接后应重新验证资源是否允许安全续传。

网络流、分段数、缓冲区、同时运行任务和进度事件应有上限。明确处理超时、重试、取消、磁盘空间不足、权限错误、文件重名和程序意外退出。完成前验证预期长度和可用的完整性信息；无法验证时如实标识，不能仅以请求结束作为成功。重定向及跨域请求不得向不相关的目标泄露 Cookie 或认证头。

FTP 及显式和隐式 FTPS 支持常见的账号密码认证与取消；SFTP 支持密码或 SSH 密钥认证，并校验主机密钥，处理首次信任、密钥变化和认证失败。协议特有的不支持续传或分段应明确退化，不能伪称支持。

HLS 由桌面端负责播放列表获取与刷新、清晰度和音轨选择、密钥获取、重试以及时间线协调；媒体库的能力必须逐项验证，不能把库的描述视为已实现。按需流式写盘，不把完整视频放入内存。处理常见 AES-128，不将 DRM 或受保护密钥交换表述为受支持。缺失分片、直播中断、非兼容轨道及合并失败时保留可恢复数据并提示用户；以完成后的实际输出验证判断成功。

## 浏览器扩展与接管

扩展继续支持现有的全局开关、最小文件大小、扩展名排除、域名黑名单、一键切换当前站点、媒体检测与语言。接管默认自动，也可选择逐项确认。被排除域名及其子域名不触发接管；当用户设置了域名黑名单而页面来源无法可靠确定时，默认由浏览器处理。文件大小最终仍未知时，沿用现有扩展行为：不因大小未知排除，继续按其他规则判断；设置页应说明这一边界。升级时保留现有用户设置；没有后端选择记录的旧安装保留 NeatDM 后端，新安装默认使用新桌面端，用户均可切换。

新桌面后端建议使用浏览器 Native Messaging，并由安装程序为受支持的浏览器登记对应宿主；扩展可选择新后端或旧 NeatDM 后端。新后端的接管使用唯一任务 ID 和持久确认：

1. 扩展判断下载是否符合用户规则及是否能够安全重放；无法安全重放或无法连接桌面端时，浏览器继续原下载。
2. 桌面端先事务性保存待确认任务，再回复明确的接单确认。扩展仅在收到确认后尝试取消浏览器下载。
3. 桌面端与扩展通过提交或恢复流程处理取消结果、通信丢失、扩展重启和重复请求；任务 ID 保证重复消息不会创建多个桌面任务。不能跨浏览器和桌面程序做原子事务时，保留可恢复状态并尽量避免丢失或重复，不承诺极端故障下绝无重复。

接管只在能安全复现请求及必要认证上下文时进行；POST、一次性链接、不可获取的认证信息、不可识别的来源等无法保证安全的情况，让浏览器继续处理。媒体手动发送也遵守站点规则和错误提示。

当前扩展通过 `ws://127.0.0.1:10007/download` 向原版 NeatDM 发消息，发送后短暂等待就视为成功，并没有原版持久接单确认。为了兼容原版，旧后端可保留这一现有行为，但必须清楚说明其保证弱于新桌面端；不能将 WebSocket 发送成功伪装成持久接单成功。新桌面端不得依赖旧协议的这个近似判断。

Native Messaging 宿主限制允许连接的扩展身份，桌面进程间通信使用当前用户受限的本地通道，并控制消息大小、验证内容和防止敏感数据进入日志。浏览器商店版与开发版扩展 ID、Chrome/Edge 安装注册以及 MSIX 环境必须实测。MSIX 注册表虚拟化可能影响宿主发现，需先验证受商店政策允许的处理方式；未验证通过时不能宣称商店版可接管。同一 Windows 用户下拥有足够权限的恶意本地程序不属于可以绝对隔离的威胁；不能声称这些措施提供不可能的完全防护。

## 安装、更新与发布

桌面端与扩展同仓库但独立发布版本。Windows x64 提供安装程序，不提供便携包；安装和卸载需正确管理程序文件、Native Messaging 注册及用户数据，并避免覆盖用户已有文件。用户是否保留设置和下载记录应在卸载时清晰处理。

GitHub Releases 的安装版支持更新通知；微软商店版使用商店更新机制。计划同时提供微软商店 MSIX 与 GitHub 安装版；商店对 MSIX 的签名不等同于 GitHub 安装包的签名。实际发布前确认签名、商店审核和 Native Messaging 是否可用，签名缺失时不能宣称安装包已受信任。安装包须包含适用的开源许可和第三方组件说明。

## 验证与交付标准

- Rust 1.100 的 Windows release 构建可复现，依赖锁定；分别报告可执行文件和完整安装包大小。
- 通过可控测试服务器验证 HTTP 分段、单连接回退、断点续传、内容变化、限速、代理认证、异常中断和磁盘错误；分别验证 FTP、FTPS、SFTP 的成功和错误路径。
- 使用覆盖 TS/fMP4、音视频分离、AES-128、清晰度、直播更新和中断的样本验证输出可解码、音视频时序和保留音轨；必要时验证 MP4/MKV 与 FFmpeg 兜底及许可。真实网站结果应说明测试条件，不能由合成样本推断全部兼容。
- 验证新后端的持久确认、超时、重复消息、浏览器取消失败、宿主或桌面程序崩溃、扩展重启和任务恢复；验证旧 NeatDM 后端兼容及其已知限制。过滤与历史扩展设置不回归。
- 在实际 Windows 环境验证安装、卸载、托盘、开机自启设置、浏览器自动启动/接管、中文输入、双语、亮暗主题和常见缩放比例；验证 Chrome 和 Edge，其他浏览器按实际支持情况记录。MSIX 与浏览器的宿主注册需单独验证。
- 在同一台机器、相同状态下记录托盘空闲、打开界面、单任务和多任务下载时的私有工作集、总工作集、私有提交量、CPU、吞吐量及峰值；与原版对照时说明测试状态。2.8 MiB 不是硬性目标，也不通过强制裁剪工作集制造低读数。
- 所有已承诺的首版协议和交互都经过验证后，才可称为完成；未验证或不支持的情况如实记录，不将探测试作视为交付。
