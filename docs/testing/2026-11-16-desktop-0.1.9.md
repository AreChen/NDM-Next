- Local macOS Rust workspace: **203 tests passed**, including the audited FFmpeg HLS/DASH integrations. Public-network smoke tests and the isolated admission fixture were excluded. Default connections, settings migration, native manifest registration, pause/resume, parallel progress, and task recovery passed.
- Browser extension: **79 tests passed**. Extension version is **1.1.4**. Its public manifest key derives fixed ID `cpapmfpgmpbpnjgibdgkfkdeblamiodm`, authorized in the macOS registration and Windows installer.
- Real Chrome acceptance: the installed unpacked extension initially had an ID absent from the native messaging allowlist. Adding that exact ID restored the popup's online status. A native Chrome click transferred a 2 MiB loopback fixture to the installed desktop app through native messaging and 16 HTTP ranges. After the user approved macOS Downloads access, the task reached `completed`; the output matched all 2,097,152 fixture bytes, SHA-256 `10ad797459a5be730fd4a6ab490cb94328bf12650c6bf4ad8defa026929edd5c`. The original browser download was removed by successful handoff.
- Fresh preferences default to 16 connections and startup enabled. Older JSON with no startup preference preserves the current OS setting; explicit connection and startup choices survive serialization.
- Packaging validates the release tag, fixed extension ID in both platform registrations, archive integrity, and exact source bytes for every archived file. ZIP includes the installation guide and Windows helper. Timestamps and permissions are normalized for reproducible output.
- Rust formatting, whitespace validation, `actionlint`, and all-target workspace clippy with warnings denied passed. The macOS-only clippy warnings introduced with the earlier platform port were also cleaned up without behavior changes.

`release.yml` requires Windows, both macOS architecture builds and extension packaging to succeed. It validates artifact provenance against the release tag, matches asset versions, checks ZIP and DMG hashes, generates `SHA256SUMS`, uploads the complete draft, and publishes it. Published assets have been checked against the successful GitHub run as recorded below.

The first GitHub run (`43794925057`) caught a pre-existing Windows shutdown race newly covered by the Windows workspace-test gate. `shutdown_releases_only_installed_hosts_and_descendant_media` failed after a second termination request queried a host image already tearing down. The fix records a successful termination request on the retained process, keeps image validation before the first request, and still waits for actual exit. The integration test repeats the full scenario three times; unrelated same-path media and other-installation hosts must survive. The incomplete run was cancelled without publishing.
